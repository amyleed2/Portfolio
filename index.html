Developer-owned AI Workflow

AI-Assisted Project Workflow

AI를 코드 생성 도구로만 사용하지 않고, 컨텍스트 설계·단계별 구현·검증 루프를 갖춘 개발 워크플로우로 활용합니다. 작업 규칙과 검증 기준을 먼저 정리한 뒤, 필요한 범위만 AI와 함께 구현하고 직접 검수합니다.

Principle

AI가 좋은 결과를 내도록 목표, 수정 범위, 금지 조건, 검증 기준을 먼저 설계합니다. AI가 제안한 결과는 기존 아키텍처, 상태 흐름, 테스트 가능성, 배포 리스크를 기준으로 직접 검토한 뒤 필요한 범위만 반영합니다.

01

Context Engineering

Context

기능 구현 전 요구사항, API 계약, 디자인 기준, 아키텍처 규칙을 문서화해 AI가 같은 기준을 참조하도록 만듭니다.

How I used AI

“AGENTS.md와 PRD를 먼저 읽고, 이번 단계의 영향 파일과 제외 범위를 정리해줘”처럼 기준 문서와 작업 범위를 함께 제공합니다.

My Decision

AI가 정리한 영향 범위는 실제 코드 의존성, 보안 정책, Firebase/DB 접근 규칙을 기준으로 다시 검토합니다.

About Me

How I Work

운영 중인 앱을 안정적으로 유지하고, 필요한 변화는 점진적으로 구조에 녹여내는 iOS 개발자입니다.

커머스, 콘텐츠, 플랫폼 도메인에서 모바일 앱을 개발·운영하며 안정성, 유지보수성, 협업 비용을 함께 봅니다. Android 개발자로 시작해 iOS로 전향하는 과정에서 두 플랫폼의 화면 구조, 배포/운영 방식, SDK/API 연동 차이를 직접 학습했고, 이 경험은 이후 iOS 앱 구조와 운영 흐름을 이해하는 기반이 되었습니다.

01

문제를 재현 가능한 단위로 좁힙니다

운영 안정성을 판단하는 방식

운영 이슈는 재현 조건, 영향 범위, 배포 리스크부터 분리합니다. Crashlytics, API 로깅, VOC를 원인 추적 단서로 보고 사용자 영향이 큰 문제부터 개선합니다.

한 번에 갈아엎기보다 안전한 변경 단위를 찾습니다

레거시를 다루는 방식

03

기술보다 먼저 적용 맥락을 봅니다

기술을 선택하는 기준

UIKit, SwiftUI, RxSwift, Combine은 상황에 맞는 선택지로 봅니다. 기존 코드, 팀 운영 방식, 테스트 가능성, 유지보수 비용을 기준으로 적용 범위를 정합니다.

반복되는 논의를 구조로 줄입니다

협업과 공통화를 설계하는 방식
