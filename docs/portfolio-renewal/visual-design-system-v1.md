# 포트폴리오 시각 시스템 설계 v1

## 문서 목적

전면 개편에 사용할 시각 언어, 공통 토큰, 내비게이션, 기본 컴포넌트를 정의한다. Career와 Projects의 카드·상세 UI는 사용자 와이어프레임을 받은 뒤 이 시스템 위에서 설계한다.

이 문서는 구현 명세의 초안이며 HTML, CSS, JavaScript는 아직 수정하지 않는다.

## 현재 시각 구조 진단

### 확인된 문제

- 거의 모든 영역이 짙은 남색 배경과 비슷한 명도의 카드로 구성되어 정보 위계가 약하다.
- `Courier New`와 모노스페이스 계열이 제목부터 긴 한국어 본문까지 과도하게 사용된다.
- 모든 섹션이 `영문 제목 + 설명 + 카드 그리드` 문법을 반복해 섹션의 목적이 구분되지 않는다.
- 보라색 그라데이션, 빛나는 점, 커서 효과가 경력과 프로젝트 증거보다 먼저 보인다.
- 기술 스택은 텍스트 태그 중심이라 기술 간 구분과 프로젝트 연결이 약하다.
- 6,000줄 이상의 누적 CSS에 과거 슬라이더, 중복 컴포넌트, 반복 미디어 쿼리가 함께 남아 있다.

### 유지할 자산

- 회사 로고 4종
- 앱 아이콘과 프로젝트 썸네일
- 아키텍처 도식
- 디자인 시스템 구조와 Code Connect 이미지
- Apple 세션·Prototype 결과 자료
- 회사 및 개인 프로젝트 스크린샷
- 이미지 확대 인터랙션

현재 `assets/images/` 아래 약 80개 파일이 있어, 새 디자인은 장식 이미지를 추가하기보다 기존 증거 자료의 배치와 캡션을 개선하는 방향이 적절하다.

## 컬러 시스템

따뜻한 오프화이트를 기본으로 하고 짙은 잉크색, 선명한 블루, 제한적인 코랄과 라임을 사용한다.

### Foundation

| Token | 값 | 용도 |
|---|---|---|
| `canvas` | `#F4F2EC` | 전체 페이지 배경 |
| `surface` | `#FFFFFF` | 주요 콘텐츠 표면 |
| `surface-subtle` | `#EAEFF4` | 보조 영역, 기술 카테고리 |
| `surface-warm` | `#EFE9DF` | Career 또는 About 보조 면 |
| `ink` | `#17212B` | 기본 제목과 본문 |
| `ink-soft` | `#3F4A55` | 보조 본문 |
| `muted` | `#69747E` | 기간, 메타 정보 |
| `line` | `#D6D9D8` | 경계선과 구분선 |
| `line-strong` | `#ADB4B8` | 선택·활성 경계 |

### Accent

| Token | 값 | 용도 |
|---|---|---|
| `blue` | `#285CE6` | 기본 CTA, 링크, 활성 내비게이션 |
| `blue-soft` | `#DDE7FF` | 블루 강조 배경 |
| `coral` | `#FF6846` | 핵심 숫자, 선택된 프로젝트 포인트 |
| `coral-soft` | `#FFE2D9` | 코랄 강조 배경 |
| `lime` | `#C9ED57` | 특수 배지, 실험·AI·신규 기술 |
| `dark-panel` | `#172334` | Hero 일부, AI Workflow, 모달 강조 면 |
| `dark-panel-text` | `#F7F8F4` | 다크 패널 텍스트 |

### 사용 비율

- 밝은 Foundation: 75%
- White Surface: 15%
- Dark Panel: 7%
- Accent: 3%

Accent는 섹션마다 여러 색을 동시에 쓰지 않는다. 한 화면의 주 강조색은 하나만 사용한다.

## 타이포그래피

### 추천 조합

- 한국어·본문·제목: `Pretendard Variable`
- 숫자·기간·기술 메타: `IBM Plex Mono`
- 대체 글꼴: `Apple SD Gothic Neo`, `Noto Sans KR`, sans-serif

Pretendard를 기본으로 선택한 이유는 긴 한국어 경력 설명의 가독성이 안정적이고 Variable Font로 제목과 본문 위계를 만들기 쉽기 때문이다. IBM Plex Mono는 숫자, 프로젝트 ID, 기술 카테고리에만 제한적으로 사용한다.

### 타입 스케일

| 역할 | Desktop | Mobile | Weight | Line height |
|---|---:|---:|---:|---:|
| Hero Display | 72px | 42px | 700 | 1.05 |
| Section Title | 48px | 34px | 700 | 1.15 |
| Feature Title | 30px | 24px | 650 | 1.25 |
| Card Title | 22px | 19px | 650 | 1.35 |
| Lead | 20px | 18px | 450 | 1.65 |
| Body | 16px | 15px | 400 | 1.75 |
| Meta | 13px | 12px | 550 | 1.45 |
| Mono Label | 12px | 11px | 600 | 1.4 |

### 사용 규칙

- 한국어 본문에 모노스페이스를 사용하지 않는다.
- 영문 섹션 라벨은 대문자와 넓은 자간을 사용하되 제목보다 작게 표현한다.
- 한 문단의 최대 너비는 약 680px로 제한한다.
- 굵은 글씨는 한 문단당 한두 곳만 사용한다.
- 문장 강조보다 숫자, 역할, 결과를 별도 블록으로 분리한다.

## 레이아웃 시스템

### Desktop

```text
Viewport 1440+
┌─────────────────────────────────────────────────────────────┐
│  Brand      Main Content 1040px          Right Index 160px │
│             ┌──────────────────────────┐  01 Home           │
│             │                          │  02 About          │
│             │                          │  03 Career         │
│             └──────────────────────────┘  ...               │
└─────────────────────────────────────────────────────────────┘
```

- 전체 최대 너비: `1360px`
- 메인 콘텐츠 최대 너비: `1040px`
- 우측 인덱스: `160px`
- 메인과 인덱스 간격: `64px`
- 좌우 안전 여백: `40px`
- 기본 12-column grid

### Laptop

- `1024px ~ 1279px`
- 우측 인덱스 폭: `132px`
- 메인 콘텐츠 유동 폭
- 좌우 여백: `32px`

### Tablet / Mobile

- `1023px` 이하에서 우측 인덱스 제거
- 상단 compact navigation으로 전환
- 좌우 여백: 태블릿 `24px`, 모바일 `20px`
- 2열 카드는 `767px` 이하에서 1열 전환
- 본문과 이미지는 viewport를 넘지 않도록 `min-width: 0` 원칙 적용

## 간격 시스템

4px 기반 스케일을 사용한다.

| Token | 값 | 사용 예 |
|---|---:|---|
| `space-1` | 4px | 아이콘 내부 간격 |
| `space-2` | 8px | 작은 라벨 간격 |
| `space-3` | 12px | 배지 간격 |
| `space-4` | 16px | 본문 요소 간격 |
| `space-5` | 24px | 카드 내부 간격 |
| `space-6` | 32px | 카드 그룹 간격 |
| `space-7` | 48px | 섹션 내부 블록 간격 |
| `space-8` | 72px | 작은 섹션 상하 여백 |
| `space-9` | 112px | 기본 섹션 상하 여백 |
| `space-10` | 152px | Hero와 핵심 섹션 여백 |

모바일에서는 섹션 상하 여백을 `72~88px`로 줄이되 카드 내부 여백은 최소 `20px`을 유지한다.

## 형태와 표면

### Radius

- 작은 배지: `999px`
- 기술 카드: `16px`
- 일반 카드: `20px`
- 대표 이미지: `24px`
- 모달: `28px`

### Border

- 기본 카드: `1px solid line`
- Hover/Selected: `1px solid ink` 또는 해당 Accent
- 카드 구분을 그림자에 의존하지 않는다.

### Shadow

- 기본 표면은 그림자 없음
- Hover: 아주 얕은 확산 그림자 한 종류
- 모달과 떠 있는 내비게이션에만 중간 그림자 사용

## 공통 섹션 헤더

모든 섹션에 같은 대형 중앙 제목을 반복하지 않는다.

```text
03 / CAREER
────────────────────────────────
회사보다 역할의 확장으로 경력을 설명합니다.
```

### 구성

- 섹션 번호와 영문 라벨
- 한국어 핵심 제목 또는 설명
- 얇은 구분선
- 필요하면 우측에 요약 숫자

### 변형

- Home: 섹션 헤더 없음
- About: 넓은 Lead 중심
- Career: 타임라인 또는 카드와 결합
- Tech Skills: 카테고리 컨트롤 포함
- Projects: 그룹 탭 또는 필터 포함 가능
- AI Workflow: Dark Panel 변형
- Contact: CTA 중심

- URL hash와 현재 섹션을 동기화
- 키보드 포커스 스타일 제공
- 화면 높이가 낮으면 압축형으로 전환

- 상단에 현재 섹션만 표시
- 선택 시 전체 섹션 목록이 sheet 또는 menu로 열림
- 메뉴 항목은 실제 DOM 순서와 동일
- 메뉴가 열리면 배경 스크롤 차단

## Tech Skills 컴포넌트

### 기본 카드

```text
┌────────────────────────┐
│                     07 │  ← 사용 프로젝트 수
│                        │
│       [SwiftUI Logo]   │
│                        │
│ SwiftUI                │
│ UIKit 병행·점진적 전환 │
└────────────────────────┘
```

### 카드 구성

- 기술 로고 또는 일관된 심볼
- 기술명
- 사용 프로젝트 수 배지
- 최대 한 줄의 사용 맥락
- 선택·키보드 포커스 상태

### 숫자 배지

- 카드 우측 상단에 배치
- 작은 원형 또는 둥근 사각형
- `07`처럼 두 자리 정렬을 적용할 수 있으나 실제 의미는 프로젝트 수
- 섹션 설명에 `숫자는 사용 프로젝트 수`라고 명시
- `0`은 표시하지 않음
- Additional Skills에는 숫자 영역 자체를 표시하지 않음

### 선택 상태

기술을 선택하면 카드 아래 또는 우측에 연결 프로젝트를 표시한다.

```text
SwiftUI · 7 Projects
Global Market / Design System / ONEstory / Encar / Note Cleaner / Mindly / FocusBoard
```

프로젝트 링크를 선택하면 Projects 위치로 이동하고 대상 카드에 일시적인 강조 상태를 적용한다.

### 기술 아이콘 자산 원칙

- 공식 브랜드에서 공개한 SVG 또는 라이선스가 명확한 아이콘 사용
- iOS 프레임워크처럼 공식 로고가 없는 기술은 텍스트 모노그램 또는 공통 Apple Framework 심볼 사용
- 서로 다른 스타일의 PNG 로고를 혼합하지 않음
- 컬러 로고를 그대로 사용하기보다 기본은 단색, Hover/Selected에서 브랜드 컬러 노출을 검토
- 로고 파일은 추후 `assets/images/tech/`에 기술 ID 기준으로 정리

### 카테고리별 표시 수

- 카테고리당 핵심 카드 4~7개
- 세부 SDK는 프로젝트 상세에만 표시
- Specialized 영역에는 MarketplaceKit, VisionKit, Figma Code Connect처럼 수는 작지만 차별성이 큰 기술을 배치

## AI Workflow 컴포넌트

### 구조

밝은 페이지 안에서 AI Workflow만 `dark-panel`을 사용해 작업 시스템의 별도 레이어처럼 표현한다.

```text
┌────────────────────────────────────────────────────────┐
│ AI-ASSISTED DEVELOPMENT                               │
│ AI가 안정적으로 작업할 수 있도록 입력과 검증을 설계  │
│                                                        │
│ 01 Context ─ 02 Routing ─ 03 Guardrails               │
│          └─ 04 Token ─ 05 Verification                │
│                                                        │
│ [선택 단계의 실제 예시]                               │
└────────────────────────────────────────────────────────┘
```

### 표현 방식

- 기존처럼 동일 크기의 긴 카드 5개를 세로로 쌓지 않는다.
- 데스크톱은 하나의 연결된 workflow rail로 표현한다.
- 선택된 단계의 짧은 설명과 예시만 상세 패널에 표시한다.
- 모바일은 단계별 compact accordion 또는 세로 stepper로 전환한다.
- 도구 태그는 하단의 `Used when appropriate` 영역에 작게 배치한다.

### 시각적 차별화

- AI를 보라색 네온으로 표현하지 않는다.
- `lime`은 현재 단계나 검증 완료 표시에만 제한적으로 사용한다.
- 코드 블록보다 체크리스트, 입력→판단→검증 흐름을 강조한다.

## 모션 원칙

- 첫 화면 제목과 Evidence Strip에만 짧은 진입 모션
- 섹션 진입 시 전체 카드가 동시에 떠오르는 애니메이션 금지
- hover는 위치 이동보다 색·경계 변화 중심
- `prefers-reduced-motion` 준수
- 이미지 확대와 내비게이션 전환은 200~280ms 범위
- 스크롤과 연결된 과한 패럴랙스 금지

## 접근성 기준

- 본문과 배경 명암비 WCAG AA 이상
- 색상만으로 활성 상태를 구분하지 않음
- 모든 카드형 버튼에 실제 버튼 또는 링크 의미 제공
- 기술 카드 선택 상태에 `aria-pressed` 또는 적절한 상태 정보 제공
- 우측 인덱스와 모바일 메뉴의 키보드 탐색 보장
- 이미지 캡션과 의미 있는 alt 유지
- 모달 열림 시 포커스 이동, 닫힘 시 원래 요소로 복귀
- ESC와 배경 선택 닫기 제공

## 반응형 검수 기준

- Hero Evidence Strip 한 줄 유지
- Tech Skills 4열 가능

- Tech Skills 2열

- 프로젝트 이미지 가로 넘침 없음

### 390px

- Evidence Strip은 3개의 작은 셀 또는 가로 스크롤 없이 세로 배치
- AI Workflow는 세로 stepper
- 44px 이상의 터치 영역 확보

## CSS 개편 전략

현재 `styles.css`에 새 스타일을 계속 덧붙이지 않는다.

### 권장 순서

1. 새 디자인 토큰을 별도 범위에서 정의
2. 새 섹션 클래스는 일관된 prefix 또는 BEM 규칙 적용
3. Home, About, Tech Skills, AI Workflow부터 새 스타일로 교체
4. Career와 Projects 와이어프레임 확정 후 해당 스타일 교체
5. 모든 섹션 전환 후 사용되지 않는 구 스타일 삭제
6. 최종적으로 중복 미디어 쿼리 통합

구 스타일 삭제는 새 구조가 정상 동작한 뒤 별도 단계에서 진행한다.

## 자산 추가 계획

향후 구현 단계에서 다음 자산이 필요하다.

- Pretendard Variable 웹폰트 또는 안정적인 로딩 방식
- IBM Plex Mono 웹폰트
- 기술 로고 SVG 세트
- 필요한 경우 프로필 이미지의 밝은 배경용 크롭본

회사·프로젝트 이미지는 기존 자산을 우선 사용하고 새 이미지 경로를 추측해 만들지 않는다.
